Key features of MoCo DC external  
 
• LM629 Servo Controller for simultaneous control of position, velocity and 
acceleration, with PID filtering.  
 
• LMD18201 Motor Driver (3 A continuous current, 6 A for 200 mSec) 
 
• Non-volatile (permanent) storage of servo parameter setups and user programs. 
 
• On-board control language with over 50 commands. 
 
• Optically isolated, wide voltage range limit switch inputs (2). 
 
• Single-ended or differential encoder inputs, up to 1 MHz, with index capability. 
 
• Position Synchon Trigger Output (since V2.91) 
 
• Limit Switch disable function (since V4.00 and HW Rev 610/611) 
 
 
• Up to 16 MoCo controllers may share a single RS-232 channel, with individual 
addressing. Two paralleled connectors simplify multi-drop cabling. 
 
• Large, two-digit LED for network address and error code display. 
 
 
• Operation from a single power supply 12 .. 24 VDC, typically 24 VDC. 
 
• Additional connector for general purpose input/output, fully supported by the 
integrated command structure. 
 
 
• Two analog inputs, 0-5 V, 8 bit resolution 
 
• One analog output, 0-5 V, 8 bit resolution, 2 mA.  
 
• Four optically-isolated inputs.  
 
• Four high-voltage, high-current driver outputs. Separate input for driver voltage 
supply.

How to communicate  
 
The MoCo series has an internal command interpreter. All data to or from the controller are ASCII-
strings. A command-string starts with a 2 letter mnemonic and dependent on the command, one or 
more parameters!  
Over 50 commands are available for programming the MoCo.  
 
Commands may be executed in various ways: 
 
Single command -- One function executed immediately 
Compound command -- Multiple functions executed immediately 
Macro command -- Compound command stored for later execution 
Sub-commands-- Single-character commands 
Address-command—Network address selection 
 
Command Termination  
 
For communications to occur,  first an existing board-address must be selected. (see Chapter 
Address-Selection) .  
A command must be terminated by the Carriage-Return Char = dec 13 (<CR>) 
 
A <CR>  without any other character, repeats the last command! 
   
Reply-Termination 
All data sent from the MoCo series are ASCII Strings. An answer string  starts with  a command 
identifier which consists off: 
the board-address, 
a one character identifier (return char),  
the channel-number,   
a colon, 
the requested data, 
the reply termination  CR LF ETX      (dec 13, 10, 3 or  hex D, E,3) 
 
Example:  TP<CR> 
 
  0P0:+000120002 <CR> <LF> <ETX> 
 the board-adress = 0

Single Command 
A single command is executed immediately after the carriage return is received 
and will be repeated each time the carriage return is received, until a different command is 
entered. With this feature, it is very easy to continuously monitor the state of an input by 
simply holding down the "Enter" key. 
Both uppercase and lowercase characters are valid, and spaces are allowed. 
Compound Commands 
A compound command is a series of single commands separated by commas rather than by a 
carriage return. In this way, it is possible to string together several commands before terminating with 
the carriage return. These multiple commands will be executed sequentially. 
 
The syntax for a compound command is: 
CMD[n], CMD[n], ...,..., (rtn) 
Once this command is entered, it remains in the buffer until replaced by another command 
and can be re-executed by transferring a carriage return. Compound commands may contain up to 15 
single commands. 
 
Example:  
ma0,ws,mr500<CR>   
ma0,ws,mr2000,ws,rp10<CR>   
 
Macro Commands 
 
Macros can be a most powerful tool for the programmer. A macro command is a 
grouping of commands to form a short program, implemented by a macro number. 
To use macros for programming the MoCo controller, insert an MD (Macro Definition) 
command as the first instruction in the command string. The syntax for macro commands 
is: 
MD(macro#), followed by a compound command string. 
 
Example: MD3,MR1000,WS500,MR-1000,WS,RP5 (rtn) 
 
In this example, MD3 defines macro #3. To call up this macro, just issue the command MC3
. 
Macro commands may be stored in any order, but you may prefer to number them sequentially 
as they are entered, because the system gives no warning if you define (and 
overwrite) an existing macro. You may wish to do this under many conditions, such as when one 
macro is called by another. It is sometimes desirable to define a complex 
motion in one macro and define key parameters such as torque, gain, or velocity, in another 
macro which is called by the main macro. 
Macro commands can call another macro, without limit. For instance, MC1 could call 
MC2, and MC2 could then call MC3 and still be able to return to complete the remainder of 
MC1. 
 
Example: MD1,MC2,MC3,MC4,MC5,MC6 
 
Macro commands may contain up to 15 single commands.

Sub Commands  
Sub-commands may be used at any time. They are most useful for interrogating variables 
without disturbing an operating program. An example would be a situation where a 
repetitive motion is in process, such as dispensing adhesive in a pattern. The operator 
would like to know the status of the command without stopping it. The sub-commands can 
be used to read the number of iterations in a loop, current system status, position, etc. A 
single character is also provided for emergency stop action. If a macro is running standard commands 
are not possible witout interrupting the macros!

Address Selection 
 
Up to 16 controllers can share one serial interface. The address selection is done by the command  
Ctrl+A + the controller address, defined by command <db>, all others are automatically de-addressed. 
 
Ctrl+A = ASCII table character 1 
 
Note:  After power-up, the controller is not addressed! Send first the address command! 
  
Example:     CtrlA5     address Controller #5  
  tp   query position 
  5p0:+000300  reply of controller #5 
   
CtrlA2     address Controller #2 
  tp   query position 
  2p0:+0002300  reply controller #2 
   
There is a interesting feature which enables sending commands to all available controllers. 
The command Ctrl-a+v+ standard command

Example: CtrlAV DV2000  defines the velocity of all boards

Limit Switch Operation  
 
Limit switch enable/disable 
 
The limit switch operation in MoCo controllers is somewhat complex, in order to give the maximum 
protection in all circumstances.  The complexity arises due the the extreme variation in conditions that 
must be protected. 
 
First and foremost is the hardware protection.  Whenever the limit switch is activated that is in the 
direction of travel, the drive to the motor is disabled within a few nanoseconds after receipt of the 
signal from the switch.  This gives absolute protection against damage by overtravel and is not 
affected in any way by software operation. 
 
However, there are applications involving the use of rotary stages where there is no need for limit 
switch protection and where disabling the motor drive might cause a problem.  For these applications, 
beginning with the MoCo2006 boards, (S/N 0610-xxx and 0611-xxx) there is now the ability to disable 
either or both limit switches using jumpers at E2 and E3.  (No jumper = limit switch enabled) 
 
At the same time, the switches are still monitored by the software protection scheme, which is 
designed to reset the motion target to the actual position whenever either limit switch is activated.  This 
action prevents continued motion if the limit switch were to be only a momentary activation.  The 
software protection scheme only tests the state of the limit switches once per millisecond. 
 
Whenever either or both limit switches are disabled by placement of the disable jumpers at E2 and E3, 
the corresponding software limit should be disabled.  In previous releases, the LN (limit on) and LF 
(limit off) commands addressed both limit switches.  Both switches are still controlled when the LN and 
LF commands are given with no following argument, to retain compatibility with previous firmware 
revisions.  However, it is now also possible to enable or disable the limit switches separately.  LN1/LF1 
enables/disables only the negative limit switch and LN2/LF2 enables/disables only the positive limit 
switch. 
 
Even with the limit switches disabled, it is still possible to make use of the negative limit switch as a 
reference input.  The FE1 (Find edge command, mode 1) command causes motion in the negative 
direction until the negative limit switch is activated.  Normal move commands will not be stopped at 
this position, so it is important that only the FE1 command be used to locate the switch position if the 
intent is to establish a reference position. There is no corresponding use available for the positive limit 
switch. 
 
After stopping, the FE4 (Find edge command, mode 4) command may be used to move in the positive 
direction until the limit switch is deactivated.  It is possible to use this process to establish a very 
repeatable reference position. 
 
When using the negative limit switch input only as a reference switch, the corresponding limit switch 
disable jumper should be installed, as well as the LF1 command being given. 
 
Switch polarity 
 
The LH and LL commands are provided so that limit switches may be supported, regardless of the 
active state.  If the switch input is a logic high level when the switch is activated, then the LH (Limit 
high) command should be used.  Otherwise, use LL (Limit low).   After selecting the active state, the 
UD (Update) command should be used to save the setup so that it does not have to be repeated for 
later use. 
 
Please be aware that the UD command saves all parameter setups, so if a gain has been changed for 
testing, the changed value will now become the value at all subsequent uses, until the gain value is 
changed and the UD command saves the changed value. 
 
The firmware for Rev. 3.0 and later always report the limit switch state as a “1” when activated, 
regardless of the LH/LL state.

Define P-Term 
   
Description 
 
 
 
Defines the P-Term of the PID-filter. This command sets the slope 
of the proportional relationship between the position error and the 
motor voltage. The higher the gain value is set, the higher is the 
stiffness of position coupling, so that an small error value causes 
a proportionally larger motor current driving the motor towards the 
target. The default gain value is usually stable. The optimum 
value depends on friction, inertia, motor power, and the resolution 
of the encoder. It must be determined by the user. If the error 
reported by an axis after completing its motion is excessive, the 
gain value may be increased in small increments until the error is 
within acceptable limits. If the axis becomes unstable and begins 
to oscillate, the gain must be reduced until the oscillation stops. 
If the error remains too high, use the di command.

Trigger Functions: 
The Moco controller is able to generate position synchrone trigger outputs. This helps to synchonize 
lasers or other measurement devices.  
Following limitations have to be considered if using this option: 
 
• Multible triggers are limited to a maximum  frequency of  500 Hz! 
• The accuracy of the trigger output is directly dependent on the actual velocity . There is a 
time delay of about 1 ms  (reaction time of a interrupt including processing time to link to the 
output) 
 
ÆÆÆÆ the error is app. 1/1000 of the actual velocity in counts/sec

Trouble Shooting: 
 
No contact with the controller: 
 
• interface settings correct? 
• RS232 connection correct ? 
• Controller addressed? 
• 2 or more controllers with same address? 
 
 
 
Motor without power or do not move: 
 
• motor connected ? 
• motor-off due excessive positioning error ? 
• after booting the controller motor always off 
• limit switch active in direction of movement? 
 
 
Excessive Positioning Error: 
 
• motor not or wrong connected  
• encoder not or wrong connected 
• speed too high 
• acceleration too high 
• torque / force too high
